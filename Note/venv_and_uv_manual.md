# 가상환경과 uv 매뉴얼

## 1. 가상환경(Virtual Environment)이란?

파이썬에서 패키지를 운영체제 전체가 공유하는 전역(Global) 공간에 설치할 경우 발생하는 프로젝트 간 설정 충돌을 방지하기 위한 공간입니다. 특정 프로젝트만을 위해 생성된 **독립적인 파이썬 실행 파일과 패키지 저장 공간**을 의미합니다.

---

## 2. 가상환경이 해결하는 문제

*   **버전 충돌 방지**  
    한 컴퓨터 내에서 여러 버전의 패키지를 충돌 없이 독립적으로 설치 및 실행할 수 있습니다. (예: 프로젝트 A는 Django 3.0, 프로젝트 B는 Django 5.0 사용)
*   **전역 환경 훼손 방지**  
    패키지 간 의존성이 얽히는 것을 막아줍니다. 프로젝트 종료 시 해당 가상환경 폴더(`.venv` 등)만 삭제하면 컴퓨터 환경을 깨끗하게 복구할 수 있습니다.
*   **협업 및 공유의 편의성**  
    현재 프로젝트에 설치된 정확한 패키지 버전 목록을 추출하여, 다른 개발자나 서버 환경에서도 100% 동일한 실행 환경을 쉽게 재현할 수 있습니다.

---

## 3. 가상환경의 동작 원리

가상환경을 활성화하면 시스템 환경변수(`PATH`)의 최우선 순위에 가상환경 폴더의 실행 파일 경로가 등록됩니다. 
*   **경로 위치:** Mac/Linux는 `.venv/bin`, Windows는 `.venv\Scripts`
*   **실행 결과:** 이후 터미널에서 `python`이나 `pip`를 실행하면 전역 파이썬이 아닌, 활성화된 가상환경 내부의 파이썬이 실행됩니다.

> **가상환경을 다시 활성화할 때마다 패키지를 재설치해야 하나요?**  
> 아닙니다. 한 번 설치된 패키지는 물리적인 파일로 유지됩니다. 재설치는 다른 환경으로 프로젝트를 공유할 때만 필요하며, 패키지 목록 파일(`requirements.txt` 또는 `uv.lock`)만 공유한 뒤 새 환경에서 명령어로 일괄 다운로드합니다.

> **활성화(Activate)의 기술적 의미**  
> 패키지를 다시 다운로드하는 것이 아니라, 운영체제에게 *"지금부터 명령어를 입력하면 이 가상환경 폴더 안의 파이썬과 패키지를 최우선으로 사용하라"*고 **경로 우선순위를 변경**해 주는 작업입니다.

## 4. uv의 탄생: 파이썬 도구의 파편화 해결

`uv`는 Rust 언어로 작성된 파이썬 패키지 및 프로젝트 관리 도구입니다. 기존에 목적별로 파편화되어 있던 여러 파이썬 생태계 도구들을 하나로 통합하여 압도적으로 빠른 처리 속도를 제공합니다.

| 역할 | 기존 도구 | uv 명령어 |
|---|---|---|
| **패키지 설치 및 의존성 관리** | `pip`, `pip-tools` | `uv pip` 또는 `uv add/lock` |
| **가상환경 생성** | `virtualenv`, `venv` | `uv venv` |
| **프로젝트 초기화 및 동기화** | `poetry`, `hatch` | `uv init`, `uv sync` |
| **파이썬 버전 다운로드 및 관리** | `pyenv` | `uv python install` |
| **전역 CLI 도구 격리 설치** | `pipx` | `uv tool install` |

## 5. pyproject.toml과 uv.lock

현대적인 파이썬 프로젝트는 `requirements.txt` 하나에만 의존하지 않고 다음 두 가지 파일로 패키지를 관리합니다.

### pyproject.toml (프로젝트 설정 파일)
파이썬 공식 표준(PEP 621)을 따르는 메타데이터 파일입니다. 프로젝트 이름, 버전, 호환되는 파이썬 버전 및 직접 필요로 하는 최상위 패키지와 허용 범위를 명시합니다.

```toml
[project]
name = "my-awesome-app"
version = "0.1.0"
requires-python = ">=3.10"
dependencies = [
    "fastapi>=0.110.0",
    "pandas<3.0.0",
]
```

### uv.lock (고정된 버전 기록 파일)
`pyproject.toml`에 명시된 패키지가 작동하기 위해 필요한 **모든 하위 패키지 목록**을 추적합니다. 
*   환경이 변해도 같은 상태를 유지하도록 모든 패키지의 정확한 설치 버전과 해시(Hash)값을 기록합니다.
*   사용자가 직접 수정하지 않으며, `uv` 명령어가 자동으로 갱신합니다.

### 팀원 간 동기화 방법
Git 등을 통해 위 두 파일을 내려받은 팀원은 터미널에 `uv sync` 명령어만 입력하면 됩니다. `uv.lock` 기준에 따라 파이썬 버전을 확인하고, 가상환경을 생성한 뒤 동일한 패키지 설치를 자동으로 완료합니다.

## 6. 자주 사용하는 명령어

### 패키지 관리
```bash
uv add requests          # 패키지 설치 및 pyproject.toml, uv.lock 자동 갱신
uv add --dev pytest      # 개발 전용(테스트 등) 패키지로 분리 설치
uv remove requests       # 패키지 삭제 및 설정 파일 정리
uv lock                  # pyproject.toml 변경 사항을 바탕으로 uv.lock 파일 수동 갱신
```

### 가상환경 자동 연동 스크립트 실행
```bash
uv run main.py
```
매번 가상환경을 활성화(`source .venv/bin/activate`)할 필요가 없습니다. `uv run`은 가상환경 내 파이썬을 자동으로 찾아 실행하며, `uv.lock`과 현재 상태가 다르면 패키지를 자동으로 동기화한 후 실행합니다.

### 심화: 파이썬 버전 및 전역 도구 관리
```bash
uv python install 3.11.8 # 시스템에 특정 파이썬 버전 다운로드 및 설치 (pyenv 대체)
uv tool install ruff     # CLI 도구를 전역 환경과 격리 설치하여 어디서나 사용 가능하게 설정 (pipx 대체)
```
