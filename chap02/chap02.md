# 파이썬 가상 환경 (Virtual Environment)

## 1. 가상 환경이란 무엇인가?
가상 환경(Virtual Environment)은 **특정 파이썬 프로젝트만을 위한 독립적인 작업 공간**입니다.
컴퓨터(전역 환경)에 설치된 파이썬과 격리되어, 각 프로젝트마다 별도의 '공구함'을 가지는 것과 같은 원리입니다.

## 2. 가상 환경을 사용하는 이유
* **버전 충돌 방지 (가장 중요):** 프로젝트 A는 `Django 2.0`을, 프로젝트 B는 `Django 3.0`을 필요로 할 때, 가상 환경을 분리하면 두 프로젝트가 충돌 없이 안전하게 실행됩니다.
* **전역 환경의 청결 유지:** 모든 패키지를 컴퓨터 전체 환경에 설치하면 패키지 간 꼬임이 발생하기 쉽습니다. 가상 환경을 사용하면 프로젝트 종료 시 해당 가상 환경 폴더만 지우면 깔끔하게 정리됩니다.
* **협업 및 공유의 편의성:** 현재 프로젝트에 사용된 정확한 패키지 목록을 추출하여 동료나 다른 환경에서 동일하게 세팅하기 쉽습니다.

## 3. 자주 묻는 질문 (FAQ)

**Q. 파이썬에서만 사용하는 개념인가요?**
> **아닙니다.** '환경 격리(Environment Isolation)'와 '의존성 관리(Dependency Management)'는 소프트웨어 개발 전반의 핵심 개념입니다.

**Q. 가상 환경을 다시 활성화 할 때마다 패키지를 재설치해야 하나요?**
> **아닙니다.** 가상 환경에 한 번 설치된 패키지는 해당 폴더(예: `venv`) 안에 물리적으로 안전하게 저장됩니다.

* **활성화(Activate)의 의미:** 패키지를 재설치하는 것이 아니라, 컴퓨터에게 *"지금부터 이 가상 환경 폴더 안에 있는 파이썬과 라이브러리를 우선적으로 사용해라"* 라고 **경로를 지정(스위치를 켜는 것)**해 주는 것입니다.
* **재설치가 필요한 순간:** 프로젝트를 다른 컴퓨터로 옮기거나 동료에게 공유할 때입니다. 이때는 무거운 가상 환경 폴더 자체를 복사하지 않고, 설치된 패키지 영수증(`requirements.txt`)만 공유하여 새 환경에서 한 번에 설치합니다.

# GPT API 기초

```python
client = OpenAI(api_key=api_key)
response = client.chat.completions.create(
    model="gpt-5.4-mini",
    temperature=0.1,
    messages=[
        {"role": "system", "content": ""},
        {"role": "assistant", "content": ""},
        {"role": "user", "content": ""},
    ]
)

print(response)
print('----')
print(response.choices[0].message.content) 
```

## 주요 파라미터

### 1. model
텍스트를 생성할 AI 모델의 이름을 지정합니다.

### 2. temperature
AI가 다음 단어를 선택할 때의 **무작위성(창의성)**을 조절하는 수치입니다. (보통 `0.0` ~ `2.0` 사이)
* **0에 가까울수록:** 확률이 가장 높은 단어만 고릅니다. 사실 확인이나 코딩처럼 예측 가능하고 일관된 답변이 필요할 때 사용합니다.
* **1 이상으로 높아질수록:** 확률이 낮은 단어도 과감하게 선택합니다. 소설 작성이나 아이디어 도출 등 창의성이 필요할 때 사용합니다.

### 3. messages
AI에게 전달할 과거의 대화 내역과 현재의 질문을 담은 리스트(배열)입니다. 

> **주의:** AI는 기본적으로 이전 대화를 기억하지 못하므로, 매번 이 `messages` 배열에 **전체(이전) 대화 기록을 통째로 담아 보내주어야** 문맥을 파악할 수 있습니다.

## 메시지 구조: Role과 Content
`messages` 배열 안에는 딕셔너리(`{}`) 형태로 각각의 메시지가 들어갑니다. 각 메시지는 **누가(role)**, **무슨 말(content)**을 했는지 정의합니다.

### 1. Role (발화자의 역할)
대화에 참여하는 대상을 세 가지로 엄격하게 구분합니다.
* **system**: 대화의 규칙과 AI의 페르소나(성격)를 설정하는 무대 감독입니다. *"너는 친절한 번역가야", "반말로 대답해"* 같은 전제 조건을 여기에 적습니다.
* **user**: 실제 서비스를 사용하는 사용자입니다. AI에게 던지는 질문이나 요청 사항이 들어갑니다.
* **assistant**: 이전에 AI가 답변했던 과거의 대화 기록입니다. 이것을 같이 넣어주면 AI가 *"아, 내가 방금 이렇게 대답했었지"* 하고 앞뒤 문맥을 이어서 대답할 수 있습니다.

### 2. Content (메시지 내용)
해당 Role(역할)이 실제로 말하는 텍스트 데이터입니다. 
* 시스템의 지시사항, 사용자의 질문, AI의 답변 텍스트가 들어가는 빈칸이라고 생각하면 됩니다.

## 코드 분석

```python
print(response.choices[0].message.content)
```
우리가 진짜 보고 싶은 것은 부가 정보가 아니라 **"AI가 최종적으로 작성한 글(답변)"**입니다. 위 코드는 복잡한 `response` 데이터 꾸러미 속에서 알맹이만 쏙 빼오는 경로(Path)를 나타냅니다.

* **response**: 전체 데이터 꾸러미를 엽니다.
* **.choices[0]**: AI가 제시한 여러 개의 답변 후보(`choices`) 중 **첫 번째(인덱스 0)** 답변을 선택합니다. (특별한 설정을 하지 않으면 1개의 답변만 오기 때문에 보통 항상 0번을 씁니다.)
* **.message**: 첫 번째 답변 데이터 안에서, 텍스트와 역할이 담긴 메시지 객체로 들어갑니다.
* **.content**: 메시지 객체 안에 들어있는 **실제 텍스트 내용물(문자열)**만을 끄집어냅니다.

> **Tip:** 이 경로를 정확히 거쳐야만 화면에 불필요한 코드 찌꺼기 없이 깔끔한 답변 텍스트만 출력할 수 있습니다.
